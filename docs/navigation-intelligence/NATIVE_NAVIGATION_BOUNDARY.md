# Native (Expo) Mobile Navigation — Scope Boundary & Follow-up

Status: **out of scope for the web Navigation Intelligence Blueprint** (intentionally deferred).

## What exists today
The native app under `mobile/` is an **Expo Router** application with file-based routing. Bottom tabs are declared **inline** in `mobile/app/(tabs)/_layout.tsx`:

| Tab | Screen file | Web registry analogue |
|---|---|---|
| Dashboard | `(tabs)/index.tsx` | `owner.overview` (`/dashboard`) |
| My Garage | `(tabs)/garage.tsx` | `owner.garage` (`/dashboard/garage`) |
| Escrow | `(tabs)/escrow.tsx` | SafePay (no 1:1 web nav item) |
| Marketplace | `(tabs)/marketplace.tsx` | `product.marketplace` (`/marketplace`) |
| Referrals | `(tabs)/referral.tsx` | `owner.referrals` (`/dashboard/referrals`) |

These tabs **conceptually duplicate** several registry features but are authored as a separate React Native codebase. The native app does **not** import the web registry (`web/src/config/featureRegistry.ts`) — that module depends on `lucide-react`/React DOM and is web-only.

## Decision
Per the Blueprint's Milestone 4.6 and its mandatory stop conditions, this programme **does not** rewrite native navigation. Doing so would expand into a native navigation redesign (new RN components, native focus/gesture handling, Expo build + device testing) beyond the web Blueprint's authorization. **Native navigation behavior is left unchanged.**

We explicitly do **not** claim "native Navigation Intelligence complete" — no native screen consumes the shared manifest yet.

## The bridge (already in place)
The framework-neutral governance manifest `shared/navigation/feature-manifest.json` (generated by `scripts/generate-feature-manifest.mjs`, guarded by the drift test) is plain JSON and is **directly importable by the Expo app**. It is the intended single source the native tabs can adopt later without coupling to web-only modules.

## Precise follow-up plan (separate, scheduled work)
1. Add `mobile/src/navigation/featureManifest.ts` that imports `shared/navigation/feature-manifest.json` and maps manifest entries → RN tab/screen descriptors (id, label, route, defaultRoles, defaultLifecycle).
2. Replace the inline `Tabs.Screen` list in `(tabs)/_layout.tsx` with a manifest-driven list filtered by the authenticated role + lifecycle (`active`/`beta` only).
3. Add an RN unit test asserting the native tab set equals the manifest-derived set for each role (mirror of `mobileNavigation.test.ts`).
4. Wire native effective-state hydration to `GET /api/features/effective` (same endpoint the web uses) so native respects runtime rollout overrides.
5. Device/emulator smoke for each role.

Until that scheduled work lands, native tabs remain as-is and are not governed by the registry.
