# LR16–LR18 identity integration and accountable decisions

LR16 continues the LR15 identity session, protected evidence, reviewer step-up and atomic decision recorder on draft PR #276. Existing routes and browser/mobile shells retain authority. Dealer and vehicle autofill remain in issue #277.

## Local OCR contract

The backend selects local-tesseract only when CARUP_IDENTITY_OCR_ENABLED=true and CARUP_OCR_PROVIDER=local-tesseract. Unconfigured service remains off. No Cloudflare invocation is needed. The pinned CPU worker uses local English model assets, receives no inherited environment or stored credentials, and returns allowlisted labeled fields. Cloudflare configuration remains governed separately. Worker limits are two active subprocesses per backend process, an 1,800-pixel maximum working edge and a 15-second deadline. This is an opt-in development candidate. Resource requirements on the intended deployment host remain open.

Valid image intake, ownership, actual upload, duplicate checks, front/reverse evidence hashes and original applicant observation custody flow through the existing service. Local OCR reads independent sides and retains field-source association. Its classification is always uncertain. Conflicts block approval, missing observations remain missing, and ordinary text on a different declared class cannot establish that class. Applicant edits are stored separately and cannot promote credibility or document classification.

Owner can replay the fixture by bringing up the disposable PostgreSQL harness, using the included synthetic image directory, starting identity-postgres-web-preview.mjs with CARUP_IDV_TEST_LOCAL_OCR=yes and CARUP_IDV_TEST_BIOMETRIC_CONTRACT=yes, and running identity-postgres-operations.mjs --local-ocr. The test harness requires loopback and a database prefixed carup_idv_test_. Each synthetic selfie is a generated geometric pattern. No raw OCR transcript is retained or sent by the worker. Protected evidence and authorized sanitized fields remain subject to the existing retention direction B.

## Decision matrix

Evaluate these rules cumulatively. Existing authorized rejection, resubmission and escalation remain available according to the case workflow, including final-state and scope restrictions.

### Biometric reconciliation and rollout

Apply `20261118024900_identity_biometric_legacy_reconciliation.sql` before `20261118025000_identity_biometric_contract.sql`. On a clean installation or the current layout the reconciliation does no work. With the recognized historic O2-X4 schema it locks and renames the legacy table, preserves sequence, policies, immutable rows and supersession history, and revokes app roles. Existing historic text-keyed assessments stay historical. The current UUID-keyed consent ledger begins without grants. An unexpected historic shape or an occupied archive name blocks compatibility work rather than folding old consents into new purposes.

The independently connected PostgreSQL harness can replay both variants. Set `CARUP_IDV_TEST_O2_X4_SQL_DIR` to a directory containing the original two migrations from the referenced O2-X4 commit and run against a fresh disposable database. Leave it unset to cover a clean installation. Use a deployment role audit, drain any legacy writers, and establish a coordinated install and recovery plan before rollout. Retention, deletion and access to the archive require the direction B policy and approval.

Signed webhooks, live provider sessions, expiry, risk thresholds and authenticated provider results remain provider-specific certification gates. Applicant requests cannot submit outcomes. The test contract denies fabricated result fields and exposes no result endpoint. Verified callback handling must bind signature and freshness to the specific provider reference, consent and evidence revision before it atomically stores a normalized result, including refusal for withdrawn or superseded cases.

## LR18 endpoint and status contract

The isolated Veriff integration extends the O2-X4 contract. Operational CarUp continues to report face matching and liveness as not performed. Consent and storage remain with the existing case. An opaque server-generated attempt reference is the only data in the Veriff create payload. The adapter is disabled unless the process is explicitly in synthetic test mode. External test traffic also requires account-specific preflight confirmation.

### OCR artifact and MRZ

Standalone backend installs now lock the OCR dependencies. The package probe verifies the English model and WASM by digest and runs the worker from an isolated artifact, including capacity, decoded pixels, timeout and restart recovery. Mac execution passed. A Linux x64/glibc install selected an ELF Sharp native binary and bundled the language and WASM assets. Actual Linux process execution and Vercel builder output remain to be qualified in a disposable runtime. Keep the provider opt-in. The 4.5 MB Function envelope constrains base64 images to about 3.37 MB before JSON overhead. Larger images require a separately governed private upload path or validated pre-upload reduction. [Vercel limits](https://vercel.com/docs/functions/limitations)

Synthetic TD3 reads across multiple fonts, layouts, scales and crop settings still contain letter/digit substitutions, filler errors and truncation. Text-based check-digit verification passes known structural tests. Do not use plausible strings, replace ambiguous characters, or elevate this to exact MRZ or authority. Operational passport classification stays uncertain. Preserve the existing OCR and strict manual-review policy while the approved evaluation corpus and legal, storage, managed-role, delivery, devices, independent review and CI gates remain open.
