# 01 — User Access and Roles TRD

## Purpose

Define how users enter and use the referral engine across web, mobile, WhatsApp, Telegram, social links, QR codes, barcodes, and agent-assisted flows.

## User roles

- Local buyer: buys cars, parts, or services inside Zimbabwe.
- Local seller: lists cars, parts, services, or space-related offers.
- Diaspora buyer: pays or arranges purchases from abroad.
- Zimbabwe receiver: receives goods, vehicles, parts, or shipment updates locally.
- General referrer: shares a code and earns a small benefit after a verified commercial milestone.
- Ambassador: higher-trust promoter with grouped campaigns and a dashboard.
- Agent/operator: supports onboarding, verification, disputes, and exceptions.
- Supplier/mechanic: sources parts, validates requests, and refers customers.

## Entry points

Users can enter through direct signup, referral link, QR scan, barcode scan, coupon entry, social post, WhatsApp chat, Telegram bot, Facebook/Instagram lead, or admin-created invitation.

## Required user journey

1. User arrives with or without a referral code.
2. System captures source, channel, campaign, and device/session context.
3. AI triage asks the user what they need.
4. User selects buy, sell, refer, book container space, request parts, import vehicle, or receive goods.
5. System creates or updates a member profile.
6. System attaches the user to the correct role and campaign.
7. Human support receives only cases that agents cannot safely resolve.
